1 · Goal, scope and words

1Goal

Hoplon & Co gets Leads from the form on hoplonco.com. The Calling Agent (Omar) calls each Lead. Omar gives the information that the Lead asked for. Omar finds Intent to Buy. Then Omar books a Discovery Call with the Manager.

This project is also a portfolio project. Each decision must be clear and explained.

Scope in three columns

v1 (this plan)

  • Outbound calls only
  • English only
  • UAE Leads only
  • Twilio + LiveKit, Azure Ireland
  • Excel and Gmail ingestion
  • Dashboard, admin only

v2 (later)

  • All parts in Azure UAE North
  • e&/du SIP trunk
  • Self-hosted STT and TTS
  • Temporal for the Lead journey

Out of scope

  • CRM updates
  • Arabic or other languages
  • Inbound calls
  • Product for clients
  • WhatsApp (calls are blocked in UAE)
  • Live transfer to the Manager

3 · The Connected Call flow

Code owns the call state machine (ADR 0001). The LLM writes the words inside each stage. The LLM never decides alone to skip a rule. A clickable prototype is in .scratch/calling-agent/prototypes/PROTOTYPE-call-flow.html.

3Stages of a Connected Call

3.1The opening (legal order)

"Hi, is this {first name}?" → "Hi {first name}, this is Omar from Hoplon and Co. You filled in a form on our website about {topic}, so I'm calling with the information you asked for. Just so you know, this call is recorded. Is now a good time for two minutes?"

Lines in the prototype are samples. The real agent writes natural words inside each stage. Persona values are configuration, not code.

Retention: recordings and transcripts are kept 12 months by default (configurable). A cleanup job deletes old data. "Erase Lead" removes personal data and keeps an anonymous record.

6 · Latency

Latency is the time from the end of the Lead's speech to the start of Omar's voice. People reply in about 0.2–0.5 s. Slow replies feel robotic and reduce bookings.

6Where the time goes (median estimate, ms)

Sources: research tickets 03 and 25. These are estimates, not measurements. Ticket 23 measures the LLM step. Real test calls recalibrate all steps.

6.1How we cut the time

TechniqueWhat it doesWhere
Own GPU next to the agentNo network and no queue for the LLM. First token in about 100 ms.Azure GPU VM
Turn-detection modelReads the words. Knows "finished" from "pause". Allows a 0.3 s wait, not 0.5 s.Deepgram Flux (default) or LiveKit model
Preemptive generationThe LLM starts before the turn ends. Optional: preemptive TTS.LiveKit setting
Stream by sentenceTTS starts on the first sentence. The LLM writes the rest.LiveKit pipeline
Warm connections, prompt cacheNo reconnect for each turn. The fixed prompt part is cached.Agent worker
Calendar prefetchGet free slots when Intent to Buy appears. Say a short line while booking.Tools

Targets (start values): median turn gap ≤ 1.2 s and p95 ≤ 2.0 s as hard limits. The design goal is 0.6–0.8 s. Real calls set the final values.

10.1Pre-dial gate (each Call Attempt must pass)

Security and abuse

  • Omar has only 4 tools: check calendar, book slot, schedule callback, set outcome. No tool can leak data.
  • Omar never tells his instructions or data about other Leads.
  • Prompt injection: Omar laughs lightly, says "Nice try!", and goes back to the topic. This is an eval scenario.
  • Maximum call length: 10 minutes.
  • Phone and email are masked in logs. Data is encrypted at rest.
  • Admin kill switch: "Stop all calls now".

Compliance hooks we build now

  • Pre-dial gate (above).
  • Call register: CSV export from the event log.
  • Data requests: "Erase this Lead" and "Export this Lead's data".
  • Consent evidence fields: timestamp, IP, form version. The website team adds the checkbox.
  • Recording notice in each opening. Call ends if the Lead refuses recording.
