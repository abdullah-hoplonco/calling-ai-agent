01What you build

Four rented services do the work. Your own code holds the rules. The model never holds the rules.

0 USDcost of the whole demo, with test data only

You press one button. You speak. The agent replies in a natural English voice. It gives you what you asked for. It offers two meeting times.

You need no phone. You need no cloud account. You need no Azure. You need four API keys, one Python package and one afternoon.

The one idea

The agent runs five stages. Your code decides which stage runs next. The model only writes the words inside the current stage. This is the rule in ADR 0001. It keeps the UAE calling rules true on every call. A prompt cannot do that.

02The call path

Audio moves one way. Words move the same way. Your code sits in the middle.

One turn, step by step

  1. You speak into the microphone.
  2. The browser sends 16 kHz µ-law audio to LiveKit.
  3. LiveKit sends the audio to Deepgram.
  4. Deepgram returns the words. It also sends a signal when your turn ended.
  5. Your state machine reads the words. It names the stage.
  6. The stage sends a prompt to Groq.
  7. Groq streams the reply, word by word.
  8. The stage checks the guards. Then it sends the words to Cartesia.
  9. Cartesia streams speech audio back to LiveKit.
  10. LiveKit sends the audio to the browser.
  11. You hear the agent.
Why the reply can feel slow

Steps 4 and 5 wait for each other. Your code cannot act before the words arrive. This is why the speech to text service sets how fast the agent feels, and why the turn detector matters more than the model.

03The latency

Four services each spend part of your budget. Here is the whole turn.

Two switches

Turn on LiveKit early generation. The agent starts to answer before Deepgram confirms that you stopped talking. Turn on the Deepgram end of turn model. Together they give back about 200 ms.

05The stages

Code holds the order. The model fills in the words.

Risk T3

The agent must never say a meeting is booked. Every tested model claims a booking now and then. The calendar must confirm first, and your code must block the words when it did not. This is not a prompt instruction. It is a guard.

06The build

Eight steps, in this order. Each one works before you start the next one.

The four keys

Three of the four need no card. Get them first, then write any code.

.env

# one console each
DEEPGRAM_API_KEY=...   # console.deepgram.com  ·  $200 credit
GROQ_API_KEY=...       # console.groq.com      ·  free tier
CARTESIA_API_KEY=...  # cartesia.ai           ·  20,000 credits
LIVEKIT_URL=ws://localhost:7880
LIVEKIT_API_KEY=...   # only for the Cloud plan

Run LiveKit on your own machine first. One binary, one command, no account.

terminal

livekit-server --dev

  1. Write the domain model

    Put the words from CONTEXT.md into core/domain.py. No logic, only names. Stage, LeadStatus, Turn.

    Done when every enum value matches a word used in the map file.

  2. Write the ports

    Put the interfaces in core/ports.py. SttPort, LlmPort, TtsPort, CalendarPort. No vendor import, ever.

    core/ports.py

    class SttPort(Protocol):
    async def start(self) -> None: ...
    async def push(self, chunk: bytes) -> None: ...
    def on_final_text(self, cb) -> None: ...
    def on_turn_end(self, cb) -> None: ...

    Done when core/ports.py contains no vendor package name.

  3. Write the Deepgram adapter

    Use the EU endpoint and the Flux model. Turn on the end of turn model. Write two callbacks: one for the final words, one for the turn end signal.

    voice/adapters/stt_deepgram.py

    DGRAM = "wss://api.eu.deepgram.com/v1/listen"

    Done when you speak into the terminal and you see your own words, then a turn end marker.

  4. Write the Groq adapter

    Use the OpenAI style base URL, the model qwen/qwen3.8-27b, and thinking off. Stream the tokens. Never wait for the full reply.

    voice/adapters/llm_groq.py

    GROQ = "https://api.groq.com/openai/v1"

    Done when the tokens print as they arrive, not in one block at the end.

  5. Write the Cartesia adapter

    Stream the audio. Start playback on the first chunk. Do not wait for the last chunk.

    Done when a 200 word reply starts playing in under 300 ms.

  6. Write the state machine and the guards

    The most important file in the project. core/machine.py names the next stage. core/guards.py holds pure functions.

    core/guards.py

    OPENING_ORDER = ["company_and_purpose", "recording_notice", "may_i_continue"]

def legal_opening(events) -> bool:
    return events[:3] == OPENING_ORDER

def may_say_booked(calendar_confirmed: bool) -> bool:
    return calendar_confirmed is True

def may_deny_being_ai(text: str) -> bool:
    return False   # always False

    Done when a unit test fails when you reorder the opening. That failing test is the deliverable.

  7. Write the LiveKit worker

    Join this order on every turn: audio, Deepgram, machine, guards, Groq, guards, Cartesia, audio. Turn on early generation.

    Done when the browser shows the agent and you hear it.

  8. Write the text seam and five scenarios

    Run the whole loop with text only. Same machine, same guards, same prompts, no audio, no network. Then write five YAML scenarios: the happy path to a booking, a price question, a request for a person, a refusal, and a question about whether the agent is human.

    Done when pytest runs all five in under two seconds with the network off.

Swap a service

Every service sits behind one interface. Change the class in the config and change no other code. This is the decision in ticket 21, and it is the reason a later provider change costs one line.

07The limits

One limit arrives before the others. It is not the one you expect.

Groq, short context 2,000 of 8,000 tokens a minute

Send one stage. Keep the context under 500 tokens.

Groq, long context 2 of 3 calls at the same time

Send the whole call again on every turn and the demo itself becomes the limit.

Cartesia 900 of 20,000 credits a month

One 3-minute demo call uses about 900 credits, so the free plan gives about 22 calls.

Groq allows 8,000 tokens a minute and 200,000 a day. One turn costs 2,700 tokens if you send the whole call. One turn costs 500 tokens if you send one stage.

Keep the context short

Reset the context at every stage change. Your state machine already gives you stages, so this is a gain from ADR 0001 rather than extra work.

Do not put Whisper on the live path

Whisper on Groq is a batch service. You send a file and you get text back 10 to 30 seconds later for a 3-minute call. Use it to check a call after the call. Use Deepgram for the live path.

08The faults

Six faults cover most of your first day. Know the fix before you meet the fault.

Symptom, cause and repair
What you seeCauseRepair
The agent cuts you offBackground noise sounds like speechRaise the interruption threshold
The agent answers too lateThe model waits for the whole turnTurn on early generation
The agent claims a bookingThe model invented itThe guard blocks the words
The agent sounds like a machineThe voice has little expressionPick another voice
The page makes no soundThe browser blocked the soundAllow sound for the page
The model stops mid callThe daily limit endedRead the limit in the log

The interruption setting is the one you will fight. LiveKit gives it to you in config, not in code.

livekit agent config

# livekit agent config
min_interruption_duration: 0.6    # ignore noise shorter than this
min_interruption_words: 2       # need two real words before a cut
false_interruption_timeout: 8.0  # repair a wrong cut after this wait
preemptive_generation: true    # start the reply before the turn ends

09The scope

Know what this demo must not do. The list is short on purpose.

  • It does not call a phone.
  • It does not read a real calendar.
  • It does not send email.
  • It does not store a lead.
  • It does not run in the cloud.
  • It does not touch a real phone number.

Each item belongs to milestone M2 or M3. A demo that tries everything proves nothing.

What you must measure

Write down four numbers. They decide the next step for the whole project.

  1. The time from your last word to the first sound.
  2. The number of tokens in one turn.
  3. The number of times the agent cut you off.
  4. The number of guard blocks in ten calls.

Read these three files first

  1. CONTEXT.md holds the words. Use those words in code, in prompts and in tests.
  2. docs/adr/0001 holds the state machine rule.
  3. docs/adr/0002 holds the LiveKit choice.

Then take step one. Get four keys.
